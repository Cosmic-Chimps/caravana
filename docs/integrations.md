# Integrations: .NET Aspire and Bella Baxter

Feature context for later phases. The rules that apply to these integrations, like optional
providers, the bootstrap cycle and declarative env, are in `.specify/memory/constitution.md`.

## .NET Aspire (Phase 2.5, after the compose translator)

The first external API client is `PublishToCaravana`, a C# Aspire hosting integration in a
separate repo, modeled on https://github.com/Cosmic-Chimps/aspire-hosting-dokploy. It publishes
through Aspire's Docker Compose output, pushes images, and POSTs compose + domains + secrets to
our API. This repo's job is to make that path work well:

- The compose translator handles Aspire-generated compose files. Test fixtures of real Aspire
  output live in `internal/compose/testdata/aspire/`.
- Aspire-style service discovery env (`services__<name>__<endpoint>__0`) is generated from
  Nomad native service discovery via templates, so Aspire apps find each other with no config.
- The Aspire dashboard can optionally be exposed as a normal app; its OTLP ports stay internal.

Gate for Phase 2.5: Bella Baxter itself deploys to Caravana via `PublishToCaravana`, with its
database on a host volume, working service discovery and HTTPS.

## Bella Baxter (dogfooding, always optional)

Bella Baxter (https://docs.bella-baxter.io/, same maintainer) is a secret management gateway
with a Go SDK, keyless OIDC auth, webhooks, an SSH CA and PKI. We use it in three ways.

Secrets (Phase 2):
- Secrets sit behind a `secrets.Provider` interface in `internal/secrets`. Nomad Variables is
  the built-in default; Bella Baxter is the first external provider, using its Go SDK.
- Prefer keyless auth: tasks authenticate to Bella with their Nomad workload identity JWT
  (validated against Nomad's JWKS endpoint), so no static Bella API key is stored anywhere.
- A Bella webhook on secret change calls our deploy webhook; the app is redeployed with its
  full, current env through the normal health-checked rollout.

Cluster hardening (Phase 3):
- Node bootstrap uses short-lived SSH certificates from Bella's SSH CA when configured, instead
  of the control plane storing private keys.
- Nomad cluster TLS certificates can be issued from Bella PKI. Fallback: certs generated by the
  control plane at install time.
